# TestovoeJob — Web API обработки HTML-страницы

POST-эндпоинт, который по переданной в Base64 HTML-странице и CSS-селектору находит элементы,
собирает значения атрибута и полный HTML каждого элемента, извлекает email из исходной страницы,
расшифровывает AES-текст и сохраняет найденные элементы в PostgreSQL. Ответ возвращается
единым DTO — и для успеха, и для ошибки.

## Стек

| Компонент | Версия и роль |
|---|---|
| .NET | 10.0 (`net10.0`) |
| PostgreSQL | 18 — хранилище элементов |
| pgAdmin | 9.18 — веб-доступ к БД |
| AngleSharp | 1.8.2 — разбор HTML в DOM и CSS-селекторы |
| Dapper | 2.1.89 — доступ к БД |
| FluentValidation | 12.1.1 — валидация входящего объекта |
| Npgsql | 10.0.3 — провайдер PostgreSQL |
| Swashbuckle.AspNetCore.SwaggerUI | 10.2.3 — Swagger UI |
| System.Text.Json | из состава .NET — сериализация, без сторонних библиотек |

Шифрование — стандартные классы .NET, email — скомпилированное регулярное выражение.
JSON — только `System.Text.Json`, кодировка везде UTF-8.

## Запуск

Нужен Docker с поддержкой compose.

```bash
docker compose up --build
```

Из трёх контейнеров (`api`, `postgres`, `pgadmin`) приложение при каждом старте собирается
из смонтированной папки `src` и запускается в том же контейнере. Схема БД создаётся
автоматически при первой инициализации тома. Данные Postgres и pgAdmin лежат в именованных
volume и переживают перезапуск.

| Что | Адрес |
|---|---|
| API | http://localhost:8090 |
| Swagger UI | http://localhost:8090/api/swagger |
| Документ OpenAPI | http://localhost:8090/openapi/v1.json |
| pgAdmin | http://localhost:8080 |

Порт БД на хост не публикуется — Postgres доступен только внутри сети compose. Учётные данные
стенда заданы прямо в `compose.yml` и `pgadmin/servers.json`.

Остановить, в том числе с удалением данных:

```bash
docker compose down -v
```

## Эндпоинт

`POST /api/process`, тело запроса — `application/json`.

### Запрос

| Поле | Назначение |
|---|---|
| `selector` | CSS-селектор для поиска элементов на странице |
| `attribute` | имя HTML-атрибута, значение которого сохраняется для каждого элемента |
| `url_b64` | URL страницы в Base64; декодируется и возвращается в ответе, по сети не запрашивается |
| `page_b64` | код HTML-страницы в Base64 |
| `key_bytes_b64` | ключ AES-256 в Base64, декодируется ровно в 32 байта |
| `encrypted_text_bytes_b64` | шифротекст AES-256-ECB в Base64 |

### Ответ

| Поле | Содержание |
|---|---|
| `is_error` | `0` — успех, `1` — ошибка |
| `error_code` | `OK` либо код ошибки |
| `error_message` | сообщение об ошибке; на успехе пустая строка |
| `elements_count` | количество элементов, найденных по `selector` |
| `emails_count` | количество email, найденных в исходном HTML |
| `url` | URL, декодированный из `url_b64` |
| `decrypted_plain_text` | текст, расшифрованный из `key_bytes_b64` и `encrypted_text_bytes_b64` |
| `elements_attr_list` | значения атрибута в порядке появления элементов |
| `emails_list` | email в порядке появления, с сохранением дубликатов |

JSON сериализуется в snake_case с отступами. Ошибка возвращается тем же DTO, что и успех,
отдельного формата ошибки нет.

Коды ошибок: `OK`, `INVALID_JSON`, `VALIDATION_ERROR`, `INVALID_BASE64_URL`,
`INVALID_BASE64_PAGE`, `INVALID_BASE64_KEY`, `INVALID_BASE64_CIPHERTEXT`, `INVALID_KEY_LENGTH`,
`INVALID_CIPHERTEXT_LENGTH`, `INVALID_SELECTOR`, `INVALID_UTF8`, `DECRYPTION_ERROR`,
`DATABASE_ERROR` (503), `INTERNAL_ERROR` (500). Остальные отдаются как 400.

## Таблица `elements`

```sql
CREATE TABLE IF NOT EXISTS elements (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    attribute_value TEXT NOT NULL,
    html_code TEXT NOT NULL
);
```

`attribute_value` — значение атрибута элемента (пустая строка, если атрибута у элемента нет),
`html_code` — полный внешний HTML элемента. Схема создаётся скриптом `db/init.sql` при первой
инициализации базы.
